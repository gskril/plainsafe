# Plain Safe

A static, local-first web UI for [Safe](https://safe.global) multisigs. It reads everything it needs from the chain through **one RPC endpoint you choose**, and signers pass signatures to each other as **plain JSON files or links**. No Safe Transaction Service, no backend, no analytics, and by default **no network request other than the RPC**.

Built at ETHGlobal Tokyo 2026 (Classic "From Scratch" track). The full product spec is [`SPEC.md`](SPEC.md); planning artifacts are in [`docs/planning/`](docs/planning/).

> **Status:** under construction during the hackathon. See SPEC §16 for the build order.

## Run it locally

```sh
bun install --frozen-lockfile
bun run dev            # development server
bun run build          # static build in dist/
bunx serve dist        # serve the build
```

Other commands: `bun run test` (unit tests), `bun run test:integration` (Mainnet checks, needs `MAINNET_RPC_URL`), `bun run lint`, `bun run typecheck`.

## The network promise

Plain Safe talks to one RPC you choose. Nothing else, unless you turn it on.

- `netguard` (`src/netguard/`) wraps `fetch`, `WebSocket`, `XMLHttpRequest`, `EventSource` and `navigator.sendBeacon` before any other module loads. Requests to hosts outside the allowlist (your RPCs, plus any capability you turn on) are blocked.
- Every attempt, allowed or blocked, appears in the in-app **network log**, with its host, path and JSON-RPC methods.
- Production builds also ship a Content Security Policy as defence in depth.
- The app refuses to run on path-based IPFS gateways (`/ipfs/<cid>`), where other sites share its origin and storage.

To confirm it yourself: open the network log in the app, or your browser's devtools Network tab.

## AI usage

ETHGlobal requires disclosure of AI tools. This project is built with **Claude Code** (Anthropic), working from `SPEC.md`:

- **Planning:** the spec was written with Claude in a planning session before the event; the transcript is in [`docs/planning/transcript.md`](docs/planning/transcript.md), and the scripts that checked the spec's Safe assumptions against Mainnet are in [`docs/planning/verification/`](docs/planning/verification/).
- **Code:** Claude Code writes the implementation step by step in the order of SPEC §16, with the human author reviewing and steering. So far that covers:
  - project scaffold and configuration (Vite, TypeScript, Biome, Tailwind, shadcn/ui components generated by the shadcn CLI)
  - `CLAUDE.md` and the screen/route map in SPEC §9.4
  - `src/netguard/` and its tests
  - the path-gateway check (`src/gateway.ts`) and its tests
  - the settings schema, the IndexedDB `Storage` service and its tests
  - the setup screen, RPC Test (chain ID and `eth_simulateV1` probe), the router shell with the setup gate, the network log drawer and the wallet connect menu
  - `src/core/` Safe hashing, signature encoding and storage layout, with tests against published safe-tx-hashes-util vectors
  - `test/integration/safe-mainnet.test.ts`, ported from the planning verification script
  - `scripts/gen-safe-deployments.ts` and the code-hash authenticity check
  - the Rpc service, pinned-block Safe loading, Add a Safe (including other chains), the Safe overview and My Safes
  - the transaction builder (native and ERC-20 sends, contract calls through whatsabi, owners and threshold)
  - the review screen: safety rules, ABI decoding, whatsabi checks and the three hashes
  - the package format and codec, signing, sharing (link, code, file) and import with verification and merge
  - execution: gas estimation, sending, receipts and plain-language Safe errors
- **Verification:** Claude Code also drives a headless Chromium (Playwright, outside the repo) against the dev server and the production build to confirm that nothing is requested before setup and that the network log lists only the configured RPCs. Signing flows are tested end to end on a local anvil fork of Sepolia with a Safe owned by freshly generated throwaway keys and a mock EIP-6963 wallet; no real keys are used.
- **Not AI-generated:** the shadcn/ui components in `src/components/ui/` come from the shadcn registry via its CLI.
